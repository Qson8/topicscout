# TopicScout — 热词判断层（选题判断 Skill）

把各平台热榜的**原始词条**变成对某个具体创作者可执行的**选题结论**：适不适合你写、能不能碰、还能热几天、具体怎么拆题。本 Skill 只做判断层，不做聚合层——聚合已有开源现成品（DailyHotApi，MIT，自托管），自研抓取引擎没有差异化（2026-11-08 作者自设的六角色评审共识，均分 5.0、五人「有条件做」、一人「不做」；评审摘要见仓库 `docs/REVIEW-SUMMARY.md`）。

## 何时用

- 拿到一份热榜/热词清单（任何来源），要决定今天写什么、放弃什么时
- 给某个账号/博主做选题会，要给出带理由的取舍时
- 复盘某个词「当时判断能热三天，结果第二天就凉了」校准判断时

## 输入

1. **创作者画像**（缺了先问，不要猜）：六个字段——内容领域与栏目、受众、发布平台、明确禁区（如不碰政治、不做带货）、日产能（每天能写几篇）、常设栏目。模板见仓库 `examples/creator-profile-template.md`（外部邀请时先问的「三问」是简版：领域、禁区、产能）。
2. **原始词条**：关键词/标题＋来源平台＋（如有）在榜信息。来源不限：DailyHotApi 自托管实例的 JSON、平台榜单页、壹念手记的每日双榜（blog.hanfucn.com/hot-keywords）、人工收集的截图文字。

## 数据源（双维度，2026-11-08 实测状态；条款状态为当日核查，须按日复核）

先分清两件事：**榜单「免登录可见」不等于平台条款允许程序取数**。下表「条款状态」列是取数端的线，与产出端的规则（见合规节）是两条线、都要守。

| 源 | 取数方式 | 条款状态 |
| --- | --- | --- |
| 今日头条热榜 | 公开接口（robots 允许） | 相对宽松，仍须低频、自核当日状态 |
| Hacker News | 官方 API / 公开页面 | 官方通道 |
| YouTube 热门榜 | 官方 Data API（需 key） | 官方通道，正规免费额度 |
| Google Trends | 每日 RSS（只有量级、无绝对值） | 官方 RSS |
| 微博热搜、百度热搜、B 站热搜、知乎、抖音 | 平台页面/接口免登录可见 | **各平台用户协议普遍明文禁止未经许可的自动化获取**（微博协议尤为明确）：不进自动取数池，只作人工浏览后手动录入的人工信号；要自动取，先取得授权或改用其官方付费 API（如百度千帆） |
| GitHub Trending | 页面抓取（**降级源**） | **无官方 API**：与被排除的源相比只是平台态度相对宽容，不改变「非官方抓取、自担条款风险」的性质；低频使用、标注来源，或不用 |
| 纽约时报最热读 | 公开榜单标题＋链接 | 仅标题与链接，不取正文、不做摘要改写；其条款禁止自动化抓取正文，数据产品走官方 API 授权 |
| Product Hunt | — | DailyHotApi 路由已坏，且无合规自动通道，不收 |
| Reddit | — | 商业使用受其条款约束，不自动抓，只作人工信号 |
| X | — | 无**免费公开**的正规来源（趋势锁在付费 API 层级，不在取数范围），缺位，不要用爬虫凑 |
| Google Play | — | 无官方榜单接口，不收 |

- DailyHotApi（MIT，自托管）覆盖上表多个源，但 MIT 是**代码许可**，不担保其各路由取数的条款正当性。启用时三条写死：①只启用免登录路由；②**禁用一切 Cookie 配置项**（如知乎的 `ZHIHU_COOKIE`）与需登录态/Puppeteer 的路由；③启用每个源前按上表自核其条款状态。海外出口机器 2026-11-08 实测：头条/知乎/抖音路由可用，百度/微博/B 站失效，GitHub Trending/HN/纽约时报可用——源存活随网络环境漂移，**以使用当天的实测为准，不引用旧结论**（包括本表的实测列）。
- 跨平台热度值量纲不同（微博的「热度」、头条的 HotValue、B 站的播放量不是一回事），**永不跨平台比大小**；持续性只按平台内口径算（在榜天数＋名次轨迹＋平台内归一化位置）。
- **输入数据处理（硬规则）**：喂入的原始响应（JSON 等）只提取标题与来源两个字段进入判断；热度等其余字段不写入任何持久文件，原始响应不落盘、不提交进公开仓库（仓库 `.gitignore` 已预置原始数据排除项）。

## 判断方法：每个词过四判

### 一判 · 适配（这个词适不适合「你」写）
- 对照画像的领域与栏目逐词判：**主线命中 / 沾边可借 / 不搭**，各给一句理由（沾边的必须说清借的角度，说不清就是不搭）。
- 同一个词对不同画像结论可以完全相反——判断永远相对于画像，不存在脱离画像的「好词」。

### 二判 · 可碰（合规与风险）
逐词扫红线，结论三档：**可写 / 降级写 / 禁碰**。
- 医疗健康：功效与疗法类只许常识与辟谣角度，禁疗效承诺（降级写）；具体诊疗建议禁碰。
- 财经：禁价格预测与投资建议，只许常识与风险（降级写）。
- 政策法规解读、突发事件：**人工确认门槛**——不自动成文，标「待确认」，当日名额由低风险选题顶上。
- 宗教民俗：只许文化赏析口径，禁功效断言（保平安、改运类）与活动信息。
- 未经证实的爆料、隐私、当事人未发声的争议：禁碰，或只写「多方说法不一致」的观察并明确信息边界。
- 名人/品牌负面：只转述已证实来源并标注，未核实数字不写成事实。

### 三判 · 持续（还能热几天）
按词的性质分类，给出建议动手窗口：
- **事件型**（突发、单点新闻）：1–2 天，过期即弃，不要追尾。
- **话题型**（讨论发酵中的议题）：3–7 天，看跨平台共振（几个平台同时在榜＝还在升温；只剩单平台＝退潮）。
- **周期型**（节气、节日、赛事、发布会）：跟着日历走，提前 1–3 天备稿，节点当天发。
- **常青型**（长尾搜索词、evergreen 问题）：不限时，排进存量慢慢写。
信号优先级：跨平台共振 ＞ 在榜天数 ＞ 单日名次。判断写明依据信号，不许只给天数不给理由。

### 四判 · 拆题（具体怎么写）
- 每个「可写」词给 **2–3 个具体拆题角度**：目标读者是谁、回答什么问题、标题句式示例。只给「GEO 价值高」这类抽象评价视为不合格——试用者要的是拿起就能写的动作。
- 事实单薄的词（只有热搜标题级信息）：拆题只能走常识/观察向，并注明信息边界。

## 输出格式

一张判断表＋一个今日清单：
| 词 | 来源（原始榜单链接） | 适配 | 可碰 | 持续 | 拆题（首选角度） |
「来源」列**每行必须携带原始来源的链接**（指到该平台的榜单页即可），不许只写来源名称——回链是把归属与流量还给来源方的动作，只写名称不算回链。然后按「今日就写（按窗口紧迫度排序）／排队／放弃（带一句原因）」三组收口。放弃的词也要留痕——判断层的价值一半在说清为什么不写。

完整示例见仓库 `examples/sample-judgment-2026-11-08.md`。

## 合规口径（硬规则，来自评审合规意见；2026-11-08 合规评审后修订）

> 先声明：本节与配套文档里的合规表述，是**作者本人据判例与平台条款作出的风险判断，不是法律意见、更不是成文法上的「安全港」**。个案判例划的是事实边界，不是免责条款；使用者须按自己的场景复核。

- **产出端**：产出只含关键词/标题、自有判断与评分、来源回链（回链须指原始来源，见输出格式）。**热度原值与完整原榜（含名次序列）不落库、不对外发布**——这是作者据《反不正当竞争法》数据专条与「实质性替代」判例口径划的风险线：标题级引用＋自有判断＋回链原始来源，是作者判断的低风险侧；整表镜像搬运（哪怕附自有加工）落在高风险侧。量化边界：单次公开产出对**单一来源**以摘录为限，**不按日全量镜像任何一个平台的原榜**；引用作者自编的二次策展小榜（如双榜样例）须如实说明其全量/摘录性质。
- **取数端**：不绕登录、验证码或任何技术措施，需要登录/Cookie 的源一律不自动取；但免登录可见**不等于**条款允许——各源按数据源节的「条款状态」列执行，协议明文禁止自动化获取的源不进自动取数池。取数端的风险由取数者按各源条款自担，本 Skill 不作保证。
- **输入端**：见数据源节的输入数据处理规则（只取标题/来源、原始响应不落盘）。
- 工具作者与使用者是同一人时责任直达个人——判断表里的「禁碰」结论不许被「就这一次」覆盖。

许可：MIT（见仓库 LICENSE）。数据归属：热榜数据归各平台所有，本 Skill 只少量引用事实性榜单信息（标题与排序）用于判断，并回链来源。

## 两周试跑协议（2026-11-08 起）

- **内部试用**：每天对当日热词双榜跑一遍四判，结果记入试跑日志（模板见仓库 `docs/TRIAL.md`）；第 14 天（2026-11-22）对照实际成文与数据复盘：判断与实际取舍的一致率、「放弃」判断的事后正确率、拆题被直接采用的比例。
- **外部试用**：目标 5–10 名真实博主（邀请由作者发出，邀请口径在 `examples/creator-profile-template.md`：给对方画像三问＋连续 3 天的判断表样例，不承诺产品化时间表）。观察指标：第二周是否还在用、是否主动要下一期。登记硬规则：**只记化名，禁记真实姓名、平台账号与联系方式，填好的创作者画像原件不提交进任何公开仓库**（本地私有文件以 `*.local.md` 命名，已被 `.gitignore` 排除）。
- **投入闸门**：两周后两条都过（内部复用成立＋外部 ≥3 人持续使用），才继续投入开发；不过则 Skill 留作内部工具，仓库停在 v0.1.x。本仓库按作者决定在试跑期提前公开，公开不改变闸门。
- 数据侧闸门（断源率）由公开双榜管道被动积累，不单独建任务。
