**给个人创作者的热词判断层——一个可安装的 Agent Skill。**

每天早上，微博、头条、知乎、Hacker News、GitHub Trending 的榜单甩给你五十个词，却不给一句意见。真正值钱的问题不是「什么在热」，而是：**这个词适不适合我的号、我能不能碰、还能热几天、具体怎么写。**

TopicScout 对着**你的创作者画像**，逐词回答这四个问题：

1. **适配**——主线命中 / 沾边可借 / 不搭，各给一句理由。
2. **可碰**——可写 / 降级写 / 禁碰。红线写死：医疗只许常识与辟谣、财经禁价格预测与投资建议、未证实爆料禁碰、政策法规与突发事件走人工确认门槛、宗教民俗只许文化赏析。
3. **持续**——事件型 1–2 天 / 话题型 3–7 天 / 周期型跟日历 / 常青型，给天数必须给信号依据：跨平台共振 ＞ 在榜天数 ＞ 单日名次。
4. **拆题**——每个可写词给 2–3 个能直接动笔的角度：写给谁、回答什么问题、标题句式。只给抽象分数、没有拆题，算判断不合格。

产出是一张判断表＋三组收口：**今日就写（按窗口紧迫度排序）／排队／放弃（每条带一句原因）**。放弃清单是判断层一半的价值——把「为什么不写」留痕。

> **TopicScout 不是什么：**它不做聚合层。聚合已有开源现成品——自托管 [DailyHotApi](https://github.com/imsyy/DailyHotApi)（MIT，致谢其作者 imsyy；自托管时只启用免登录路由、禁用一切 Cookie 配置，并先自核各源当日条款）或任何热榜产品，把它们的产出喂给本 Skill 即可。在我们自己的调研与 2026-11-08 的内部六角色评审（均分 5.0、五人「有条件做」、一人「不做」；该评审为作者自设的角色评审、非独立第三方评估）看来，判断层是目前最少有人做的一层，自研抓取引擎是长期维护负债。见 [docs/REVIEW-SUMMARY.md](docs/REVIEW-SUMMARY.md)。

## 诚实与合规口径（内置硬规则，不可关）

- 产出只含：关键词/标题、自有判断与评分、**回链原始来源**的链接。**热度原值与完整原榜（含名次序列）不落库、不对外发布**。标题级引用＋自有判断＋回链原始来源，是作者据「实质性替代」判例口径划出的风险线——是讲了理由的立场，**不是成文法上的安全港、不是法律意见**；整表镜像搬运落在这条线的错误一侧。
- 不绕登录、验证码或任何技术措施——但免登录可见不等于条款允许：每个源都带「条款状态」（见 skill/SKILL.md），协议明文禁止未经许可自动化获取的源只作人工信号。**X 无免费公开的正规趋势源，明确缺位，不用爬虫凑**；Google Play 无官方榜单接口，不收。
- 热度值永不跨平台比大小（各平台量纲不同）；持续性只按平台内口径算：在榜天数＋名次轨迹＋平台内归一化位置。
- 判断永远相对于画像：同一个词，对科技号可以是「今日就写」、对育儿号可以是「放弃」——不存在脱离画像的「好词」。

## 快速开始

1. 把 [`skill/SKILL.md`](skill/SKILL.md) 放进你的 Agent 技能目录（Muse、Claude Code 或任何兼容 SKILL.md 的运行时）。
2. 填一份创作者画像——用 [examples/creator-profile-template.md](examples/creator-profile-template.md)：六个字段（领域与栏目、受众、发布平台、明确禁区、日产能、常设栏目）。
3. 把任何一份热榜交给 Agent（DailyHotApi 的 JSON、榜单页、截图文字、或壹念手记每日双榜 blog.hanfucn.com/hot-keywords），让它跑今天的四判。原始响应只取标题与来源两个字段——热度值与原始数据不落盘，是 Skill 写死的数据处理规则。

## 样例产出

[examples/sample-judgment-2026-11-08.md](examples/sample-judgment-2026-11-08.md) 是一份真实示例：2026-11-08 双榜（国内 10 词＋海外 8 词）对着一个真实四分类博客的画像逐词判断，并附「当日实际」一节——当天该博客实际发出的文章与判断的「今日就写」组对应、放弃组的词当天也都没有成文。该样例引用了当日双榜的全部 18 条标题（双榜本身是作者二次策展的小榜、不是任何单一平台的原榜），不含名次与热度、经重排并附原创判断；样例内同时披露了它的分桶与榜页当日动作不一致的 4 处。须说明：这是当晚回溯写的演示，不是事前预测日志；事前日志按下方试跑协议逐日积累。

## 状态：两周试跑（2026-11-08 → 2026-11-22）

TopicScout 按作者决定**在试跑期提前公开**，试跑结论仍决定它是否值得继续投入：

- **内部试用**：每天对当日双榜跑四判并登记（模板见 [docs/TRIAL.md](docs/TRIAL.md)）；第 14 天盘点判断与实际取舍的一致率、「放弃」的事后正确率、拆题采用比例。
- **外部试用**：5–10 名真实博主，由作者本人邀请（邀请口径在画像模板里）；只看一个信号——第二周是否还在用。
- **闸门**：两条都过（内部复用成立＋外部 ≥3 人第二周持续使用）才继续投入；不过则留作内部工具，本仓库停在 v0.1.x。方法全文见 [docs/METHODOLOGY.md](docs/METHODOLOGY.md)。

TopicScout 的方法出自一条每天真实运行的生产管道——作者博客的每日双榜与由它供稿的文章；Skill 本体处于试跑期，前瞻判断自 2026-11-09 起逐日登记（见 docs/TRIAL.md）。若它对你有用，给个 star 帮它被找到。
